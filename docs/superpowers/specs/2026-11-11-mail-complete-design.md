# Complete Mail B and optional parity design

Date: 2026-11-11. Status: implementation authorized by the user's instruction to complete B, extras, PR, release and production deployment. This supersedes the historical B implementation freeze, not the production sending default. Based on pinned Mail5.12.5 implementation, accepted A/D/C and local B0.

## Intent and constraints

Complete the owned-account Mail workflow with explicit approval, durable outcome evidence and bounded work. Keep production MCP transmission disabled throughout implementation, acceptance and deployment; no real email is sent by this task. Synthetic SMTP/IMAP/ManageSieve fixtures prove behavior. Send, schedule, cancel, Sent repair, export, indexing, snooze, filters and absence configuration have separate denied-by-default permissions and current connection selection. Missing provider guarantees fail closed.

Continue using PHP, Nextcloud native services, the guarded Mail dependency and the existing operation journal. Pin the new dependency to NC35.0.2 with directly connected PostgreSQL16 or the separately qualified transactional MySQL provider. Preserve native v1–v10 artifacts and legacy admission. Credentials stay in native setup; no credential/key material crosses MCP or receipts. Delegated/global administration, permanent deletion, arbitrary Sieve programs and key lifecycle remain excluded.

## Approach and tradeoffs

The stock outbox persists SMTP state after transmission, retries selected failures, skips missing attachment bytes, and falls back from missing aliases. Wrapping its existing send entry would retain these defects. Patching the entire ordinary outbox would change unrelated native users' behavior. Use a dedicated native approved-delivery queue with frozen payloads, durable attempt evidence and the existing per-owner physical-session lease; MCP owns authorization/confirmation and calls closed native actions. This is the implementation choice for the already approved native guard architecture. It costs an additional native table and worker, and avoids exposing ordinary stock retry behavior to approved MCP messages.

For content reads reuse the native transport budget hook already installed for refresh, with a different bounded read grammar. A size preflight or partial FETCH alone is insufficient. Optional settings use narrow structured native adapters, never generic objects or arbitrary scripts. Existing bounded metadata batches and alias/signature administration remain the batch/identity foundation.

## B: approval, queue and outcomes

A preview shows the exact owned sender (account/alias name/address), final To/Cc/Bcc, subject, plain/HTML body, reply parent, attachment names/bytes/SHA256, draft/account/alias revisions and schedule instant/timezone. Reject groups unless expanded once into the approved explicit address set. Refuse crypto modes or MDN behavior whose bytes/transmission cannot be preserved; never downgrade them. Confirmation rereads the source under DraftCoordinator owner lease and compares the canonical content/identity/attachment revision. Then render and persist frozen SMTP headers/body/envelope and FCC bytes before any remote effect. Generated Date/Message-ID/MIME boundaries are protocol metadata, generated once at confirmation and frozen for the attempt; they do not change the approved sender/content. Missing attachment bytes or changed/missing alias fail before admission. No body, MIME, credentials or private handles enter operation receipts/logs.

Dedicated release associates the protected draft with the immutable queue entry atomically under the owner lease. Keep the native draft protected; never clear its marker into a stock outgoing row. While an entry is active/uncertain/accepted, native UI edits/deletion/attachment changes must respect the queue association. Cancelled entries release their source for a new explicit approval. An identical operation replays its admission/entry ID; never infers delivery from queue/draft deletion. A read-only native lookup by originating operation key recovers queue evidence if the queue commit succeeded but the MCP delivery-ID checkpoint was lost. Source holds persist; account/alias holds release after accepted SMTP and verified Sent copy so completed history cannot freeze account administration forever. Queue status is distinct from journal admission success.

Delivery states: queued, blocked, attempting, accepted, uncertain, cancelled. Sent-copy states: not_started, pending, attempting, verified, uncertain. A committed CAS to attempting happens before SMTP transport construction/submission; commit acknowledgement loss stops before wire. An attempting row left by a crash is permanently uncertain for dispatch purposes and never automatically requeued. A definite final DATA success yields accepted, not delivered. Exceptions after the pre-wire checkpoint are conservatively uncertain unless native protocol phase proves rejection. Partial RCPT or lost DATA acknowledgement never causes whole-envelope replay. New sends after uncertainty require a separately approved new draft/action, never retrying the original attempt.

Scheduling stores UTC epoch plus an explicit IANA timezone/display instant in the approval. Due selection is bounded to 50. An MCP background worker launches one signed, fresh CLI child per item with a20-second absolute process/alarm deadline and a25-second ticket. It rechecks enabled user/app, originating persistent OAuth connection, current selected tool/grant/resource scope and native queue identity on each item. Basic/session connection zero cannot authorize deferred transmission. Revocation blocks dispatch. No refreshed/implicit consent. Worker/worker/cancel/release share DraftOwnerLease and row CAS; cancellation succeeds only before attempting and never means recall. Native account/alias changes are coordinated or invalidate the approved identity before wire.

Sent repair has an IMAP-only implementation and accepts only durable SMTP-accepted entries. It appends the frozen FCC to the approved owned Sent mailbox, persisting attempt before APPEND and proof after APPENDUID/readback. Missing target stays pending. Lost APPEND acknowledgement stays uncertain; no blind append retry or SMTP call. A bounded reconciliation may prove an existing exact FCC copy, never derive SMTP acceptance from Sent existence. Initial native dispatch records accepted/pending; complete normal Sent copying only when its target was bound in initial approval, otherwise require the separate approved copy-only action. Ancillary event/cache failures do not permit resend.

## Extras

- **Content/export:** fresh private client, budget installed before login, same selected mailbox/UIDVALIDITY and exact UID; readonly PEEK only. Raw and individual decoded parts at most 25 MiB, aggregate wire at most 40 MiB, bounded protocol lines/count/deadline before allocations. Crypto refused. Export one EML to Files using confirmed IncomingFileWriter admission, SHA256, no overwrite, operation checkpoint/status/replay. Existing read/save attachment tools retain small response bounds; larger parts go directly to Files without base64 in tool output.
- **IMAP drafts:** bounded cached search restricted to configured owned Drafts folder and draft flag. Import is an explicit copy into a protected local draft, preserving supported recipients/body/reply parent/owned sender and bounded attachments, with exact source generation/content approval. Never call handleDraft or emit the source-deleting DraftMessageCreatedEvent. Unsupported/crypto MIME refuses rather than silently dropping content.
- **Body index:** explicit bounded indexing of at most 20 selected owned messages using capped native content, no implicit mailbox crawl. Native generation-bound text index (PostgreSQL tsvector/GIN; other providers closed until qualified), keyed by owner/account/mailbox/UIDVALIDITY/UID and content revision. Search at most 50 rows with keyset pagination, intersect current native cache/generation and effective scope. Return coverage/limits; never claim all mailbox content is indexed. Index updates are confirmed local writes, no mark-read/sync.
- **Resource scopes:** extend existing saved policy with typed Mail account/folder resource identities and validation. A selected account permits its owned folders and account actions; a selected folder permits only that folder's message operations. Account settings/composition/send require whole-account access. Enforce before content/metadata, source/destination/reply/forward/Files references, UI selection, native worker, status/replay and new index. Unreadable scope fails closed. Parameterless lists filter; global account creation/tag administration requires unrestricted scope. Do not open the activation barrier until the complete consumer graph passes tests.
- **Snooze:** explicit one-message move into configured snooze folder plus durable wake intent, using qualified guarded move/COPYUID and both mailbox generations. Wake/cancel share ownership and durable pre-wire intent, recheck current originating authorization, require exact original destination, no INBOX fallback. Lost move acknowledgement remains uncertain; no automatic repeated move. Thread-wide unbounded operations absent.
- **Filters/absence:** bounded structured ManageSieve reads/writes with current script name/hash, exact preview, shared native UI/background owner lock, bounded transport and readback. Preserve unknown script sections; refuse unsafe unsupported program shapes. Nontransmitting fileinto/flags/keep/stop are independently permitted. Vacation enabling or redirect requires the separate transmission gate and explicit action approval; production remains disabled. Disable remains available. No raw script or credentials in tools/logs; unsupported server extensions are reported honestly.
- **Identity settings:** retain current alias CRUD/signatures and add only native validated signature mode for account/alias with preservation of provisioned/crypto bindings. No invented default identity and no assertion that alias creation proves provider send-as permission.
- **Legacy cache provenance:** inspect bounded per-mailbox eligibility; prefer the native synchronization/rebuild that records real generations and retains original messages/tag history. Do not bulk reset production cache as part of deployment. Leave any unsafe mailbox explicitly blocked rather than stamping a guessed generation.

## Acceptance and delivery

Native tests use real primary DB sessions plus recording fault-capable SMTP/IMAP/ManageSieve. Cover worker death, unknown local commit, SMTP partial recipients/timeouts/DATA acknowledgement loss, concurrent workers/cancel/source edits, accepted SMTP with missing Sent/lost APPEND, malicious oversized literals, UIDVALIDITY/reselection, scope revocation and cross-owner IDs. No duplicate SMTP submission or unverified move/append replay. Run regression/static analysis/browser/catalog/docs/API/package checks, fresh review, pin immutable source/native artifacts and hashes. Publish PR against main, versioned release/source kit, then consistent production backup/freeze/drain/migrate/fresh-worker verification and reopen admission. Preserve grants/connections/scopes and disabled sending. Rollback must match database/config/data/object storage, never code-only after migration.
