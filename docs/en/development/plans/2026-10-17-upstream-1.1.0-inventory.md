## Reconciliation rules

- Production entries map to final capability owners; never import `Service` or
  `Tools` as runtime compatibility trees. The main plan defines the ownership map.
- Port behavior assertions from source-inspection tests into existing behavioral
  or architecture checks where the old file layout no longer exists. Record why
  an assertion is superseded; never count a deleted test as covered automatically.
- Keep all five versioned migrations and the seed step under their original class
  identities. Preserve host fixtures and migration history as permanent code.
- Retain local dependency locks, stronger analysis, generated bundle pipeline,
  documentation provenance and the Deck guide correction. Upstream changes neither
  `mcp/composer.json` nor `mcp/composer.lock`; there is no dependency upgrade to infer
  from the release number. Any newly required dependency needs its own evidence.
- P3 creates scope snapshot/activation primitives and conservative deletion cleanup
  because its resolver, undo and user lifecycle already need them. P5 adds public
  writes and all resource consumers; no optional dependency or unrestricted shim.
  `PolicyWriterTest` is split across P2–P5; P2 ports kernel cases, not every future
  command test. Source phase ranges describe ownership, not a license to skip cases.
- Native harness entries have P7 ownership; their security scenarios also define
  acceptance in earlier feature phases. P9 verifies the final package identity.
