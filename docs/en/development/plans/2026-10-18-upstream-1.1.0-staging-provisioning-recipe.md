## 4. Security decisions made concrete

1. **No unattended password arguments.** Reviewing the official Docker entrypoint
   showed its automatic installation expands password values into `occ` arguments.
   The recipe omits the automatic admin/DB install environment and uses the pinned
   [NC35 install command's hidden prompts](https://github.com/nextcloud/server/blob/v35.0.1/core/Command/Maintenance/Install.php).
   The private operator channel and actual image behavior must be confirmed before
   entering secrets; no credentials were generated or supplied during preparation.
2. **Separate sockets and lifecycle.** Private and public ports map to different
   gateway listeners. Public review routes additionally require tmpfs allow-files,
   absent after startup. A two-hour system-level close service stops only the
   explicit `mcp-staging-110` gateway, cutting active streams, then revokes the
   recorded exposures. Failures remain errors and retain the record for follow-up.
   Actual expiry/restart/revocation and external denial are still untested.
3. **S1 backup before S2.** The runbook preserves the fresh native fixture baseline
   remotely before installing MCP. LDAP config/data and external fixture state are
   included; LDAP mutations stop and its service is stopped during raw volume
   copying. The image's automatic daily LDIF is disabled. MariaDB uses a logical
   dump, never live raw DB files. The restic wrapper reads backend credentials from
   files into its own process, never argv; app services do not receive those secrets.
4. **Resources and isolation.** The backup worker has a separate egress network
   and read-only source mounts. Its narrow `DAC_READ_SEARCH` capability permits
   reading service-owned files. Both Nextcloud instances have separate identities,
   databases, caches and state. The private mail sink is shared on the two internal
   networks solely to capture fixture mail; it does not relay externally.
5. **No placeholder deployment.** Paths/subnets/hosts in `validation.env` are
   deliberate test inputs. Rendering requires actual approved values. No active
   config, installed timer, account or backend repository exists. The backup
   schedule is a contract for coordinated orchestration, not a timer that backs up
   live files. Target-specific recovery mounts/imports remain blocked pending S1.

## 6. Review corrections and evidence

The recipe/pin review found and corrected the following local issues before the
documentation commit. The immutable input lock and the MCP candidate are unchanged.

- **Validation could be disabled.** Python optimization removes `assert` statements.
  The validator now uses unconditional error checks. A public-bind regression was
  observed to pass incorrectly under `-O` before the correction and is now rejected
  in both modes. See the [Python language reference](https://docs.python.org/3/reference/simple_stmts.html#the-assert-statement).
- **Pins were not bound to services.** Previously, a service could select another
  service's otherwise valid locked image. An explicit service-to-image mapping now
  rejects that mutation; the regression failed before the fix and passes afterward.
- **Shutdown could inherit another endpoint.** The close helper now uses absolute
  executables, the explicit local Docker socket and project name, and removes
  inherited Docker/Compose/staging overrides from child-process environments.
  Mocked tests prove the ambient remote-target case cannot redirect the call.
  [Compose environment behavior](https://docs.docker.com/compose/how-tos/environment-variables/envvars/)
  explains why a project-name flag alone does not select the daemon.
- **Malformed exposure records escaped structured reporting.** Non-object records
  now fail explicitly after attempting gateway shutdown. Wrong-project records
  cannot supply revocation targets. Missing/malformed metadata and command failures
  remain errors, with no retry that hides a failed close.
- **A previous timer could already be elapsed.** The runbook now requires reset and
  rearming while ingress is still closed, then verification of a future monotonic
  deadline within two hours before any allow-file is created. `active (elapsed)`
  is not accepted as an armed deadline. Never rearm or extend an open window. See
  [systemd timer semantics](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html).

The corrected close helper was exercised only with mocked processes. Neither a
real gateway shutdown nor exposure revocation was run. Fresh OCI/config/archive
checks verify identity and declared compatibility, not vulnerabilities, cryptographic
app signature acceptance, isolation enforcement or recovery readiness.

The access-log template omits URI/query/headers; the bundle does **not** implement
redaction of vendor error logs or of the external exposure layer. Lack of verified
secret-safe logging blocks all credential-bearing HTTP tests, including
private OAuth/recovery controls, rather than assuming private storage solves it.
The selected operator must retain diagnosable errors without leaking credentials;
no error suppression or new privacy guarantee is claimed by this documentation.
