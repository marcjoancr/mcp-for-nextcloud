# Upstream 1.1.0 human review checklist

Status: **all approvals pending**. This checklist is the human acceptance companion
to the [staging plan](2026-10-18-upstream-1.1.0-staging-acceptance.md), not an execution
report. It does not authorize deployment, exposure, push or sending data to clients.
Technical closure and AI-assisted review do not establish human linguistic approval.

## Review records and ownership

Assign a competent human reviewer for each of `es`, `ca`, `pt-BR` and `pt-PT`,
runtime-language reviewers for English, German, Spanish and Brazilian Portuguese,
a technical/security reviewer, an accessibility tester and an operations owner.
One person may cover several roles only where competent; record each role explicitly. Brazil and Portugal require separate judgments.

For each page or scenario, record in the future staging report:

| Field | Required value |
| --- | --- |
| Review ID | H-DOC page/locale, H-SEM item, H-UI item or H-OPS item |
| Reviewer / role / UTC date | Actual human identity and responsibility |
| Inputs | Full source revision; translated path and reviewed revision/blob hash; package hash for rendered reviews |
| Environment | Browser/client/assistive technology/host versions where applicable |
| Findings | Concrete omission, ambiguity or technical error; linked correction and retest |
| Evidence | Sanitized reference and explicit scope; no credentials or personal data |
| Verdict | Pending, changes required or approved; reason for any scope limitation |

All approvals apply to exact reviewed bytes. Changing an English claim or a
translation reopens its affected approval. Do not certify by bulk replacing metadata
or treating a green command as a reviewer. Preserve unresolved findings with owners;
no invented reviewer, date, signature or “reviewed” status.

## H-SEM — Security and compatibility meaning

The technical reviewer checks each item in English and with the locale reviewer.
Use [permissions](../../guides/permissions.md), [OAuth](../../reference/oauth.md),
[file protection](../../guides/file-protection.md) and
[recovery](../../installation.md#upgrade-and-recovery) as canonical contracts.

- [ ] **H-SEM-1:** Authentication, Can connect, personal connection, operation grant,
  resource restriction, exclusion tags and native ACLs are distinct requirements.
  Individual overrides precede trusted group grants; groups do not deny or narrow.
- [ ] **H-SEM-2:** Unknown means uncertainty, never implicit allow, definite denial
  or justification to erase credentials. An uncertain operation grant omits the
  affected discovery entries while independently allowed tools/prompts remain;
  direct operations depending on it fail temporarily. Unreadable policy storage
  fails the dependent listing/call, not a successful empty result. Do not translate
  these distinct situations as one blanket rule about all discovery responses.
- [ ] **H-SEM-3:** Empty selected scope means no resources; unrestricted means no
  additional filter. Files, Calendar and Tasks scopes are independent; VEVENT and
  VTODO stay distinct. Notes/Contacts/Deck/Talk gain no imaginary module scope.
- [ ] **H-SEM-4:** Revocation, disconnect, service shutdown, client withdrawal and
  scope edits have different effects. A committed change with pending cleanup is
  not a failed commit or necessarily an unreadable policy. Undo/regrant/re-enable
  never revives old OAuth credentials. Service shutdown preserves the personal
  connection preference; app passwords require separate native Security management.
- [ ] **H-SEM-5:** A client ID is not a secret or grant. Native loopback ports may
  vary, custom callback ports must match exactly. Published identity host removal
  applies even with cached metadata. No instructions bypass consent, PKCE or CSRF.
- [ ] **H-SEM-6:** Folder refusal and null folder URLs are intentional protections.
  Structured-reference filtering does not promise free-text DLP, remote tag
  inheritance or tag equivalence across distinct mount IDs. Native freshness and
  lock limitations remain visible; audit messages are not a guaranteed audit trail.
- [ ] **H-SEM-7:** Ordinary upgrade maintenance is different from credential-cutting
  shutdown/recovery. Recovery restores coordinated state, invalidates restored
  credentials and reviews restrictions before reopening; file-only downgrade is
  unsafe and a SQLite rehearsal is not universal backup certification.
- [ ] **H-SEM-8:** Version support, optional app requirements and external-client
  setup are accurate for the tested versions. Translate UI instructions against
  the rendered candidate; report stale English labels rather than copying them
  blindly or silently inventing divergent translated instructions.

## H-UI — Runtime language, interaction and accessibility

Perform on the S5 staging candidate; record exact browser, theme, viewport, zoom
and assistive-technology versions. Use fixture names in captures.

- [ ] **H-UI-1:** Review the complete changed administration, personal and consent
  journeys in English, German, Spanish and Brazilian Portuguese. Verify placeholders,
  plurals, truncation and error messages in context. Source/catalog parity alone
  is not rendered-language approval; record any Nextcloud locale fallback.
- [ ] **H-UI-2:** A German speaker explicitly reviews the two local additions in
  `mcp/l10n/de.json` and their generated catalog counterpart, alongside the imported
  catalog's changed journeys: `Permission unknown` → `Berechtigung unbekannt`, and
  `MCP access cannot be checked right now. Try again shortly.` →
  `Der MCP-Zugriff kann derzeit nicht überprüft werden. Versuche es in Kürze erneut.`
  Check that neither implies permanent denial or successful connection.
- [ ] **H-UI-3:** Keyboard-only navigation reaches all five tabs, filters, pagination,
  drawers, dialogs and actions in a logical order. Focus is visible; dialog close
  returns it sensibly; Escape/Tab behavior has no trap or inaccessible action.
- [ ] **H-UI-4:** With a named screen-reader/browser pair, confirm labels, roles,
  state and live announcements for loading, success, conflict, unknown and failure.
  Color alone never carries essential permission or error meaning.
- [ ] **H-UI-5:** Reset confirmation remains stable when delayed announcements arrive.
  Undo's ten-second availability pauses on pointer hover/keyboard focus; expired
  receipts and intervening revisions cannot silently overwrite newer state.
- [ ] **H-UI-6:** Switching Alice/Bob during delayed browse/reload/save/undo and error
  responses never replaces the new editor with old data. Detached controls cannot
  write against another user. Conflicts reload without automatically replaying.
- [ ] **H-UI-7:** Light/dark and the intended custom theme, narrow viewport and 200%
  zoom retain readable text, focus and usable controls. CSP blocks no required
  assets; no security setting is weakened for visual compatibility.
- [ ] **H-UI-8:** Non-admin users see only their own read-only restrictions and
  connection controls; administrator diagnostics do not leak into MCP/personal
  responses. Client revoke versus personal disconnect versus service shutdown is
  understandable before committing an action.

Accessibility approval covers these tested combinations and tasks, not an
unperformed comprehensive standards certification. An inaccessible mandatory
operation blocks acceptance; do not relabel it as a cosmetic issue.

## H-OPS — Operational and final acceptance

- [ ] **H-OPS-1:** Operator/security owners approve the S0 topology/origin and client
  coverage, version-appropriate S1 fixtures, S2 migration/preservation results,
  S3 notification/mail-sink observations and S3–S4 security evidence with concrete
  IDs. No missing app/client/reviewer is counted as a pass; whole required scenario
  rows cannot be waived as not applicable to obtain full closure.
- [ ] **H-OPS-2:** Owners understand and accept the measured cache/event windows,
  local-only federated tags, distinct mount IDs, external-group constraints and
  documented lock/reference limits. An unacceptable limitation blocks this topology.
- [ ] **H-OPS-3:** The backup operator witnesses S6 using the actual database and
  recovery tooling. Unexpired saved credentials (or the explicitly recorded
  restored-lineage pre-cut controls defined in S6) are rejected after service and
  personal reconnection while fresh controls work on the same path. Record expired
  backup artifacts separately: maintenance, firewall denial or expiry is not
  revocation evidence. When using a new pre-cut control, verify the recorded
  epoch/generation cut covers both it and the saved credential as required by S6.
  Native app-password checks also use a native authenticated endpoint. Record measured RPO/RTO against agreed
  definitions/targets, confirm the ingress barrier, and leave MCP/test access closed.
- [ ] **H-OPS-4:** The maintainer verifies all 96 current per-page approvals, runtime
  language/accessibility records, fixed-defect retests and the final artifact hash.
  Any later distributed correction triggers the S7 requalification rules.
- [ ] **H-OPS-5:** Sign the staging report with a scope-limited verdict. Keep GitHub CI,
  signing/publication and production deployment explicitly unexecuted. Approval
  of staging does not authorize these actions or certify a newer upstream revision.

A translation may remain a clearly labeled draft under repository policy, but
that does not complete this checklist's full human-review objective. If a reviewer
is unavailable, retain `Pending` and report partial acceptance rather than removing
the locale, falsifying provenance or quietly lowering the closure criteria.
