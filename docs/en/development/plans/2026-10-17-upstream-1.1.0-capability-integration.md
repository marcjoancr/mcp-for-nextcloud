# Upstream 1.1.0 capability integration plan

> **For agentic workers:** use `superpowers:executing-plans` to implement approved
> phases in order. Use checkbox steps to record progress. This document authorizes
> no implementation, host installation, push, pull request or deployment.

**Goal:** integrate the original project's 1.1.0 security, compatibility and product
changes into the completed capability architecture, preserving attribution and
leaving no legacy implementation or transition folders.

**Architecture:** port behavior and its evidence into the existing owners; do not
restore upstream's `lib/Service`, `lib/Tools` or global administration scripts.
Split the new policy command responsibilities while retaining one atomic transaction
boundary. Keep native persistence, events and authentication semantics observable.

**Tech stack:** PHP >=8.2, Nextcloud 32–35, native DAV/OAuth, PHPUnit 10.5,
PHPStan, native JavaScript modules, pinned Node 24.21.x/npm 11.19.x and Playwright.

**Spec:** [architecture specification](../architecture-specification.md),
[local closure](2026-10-17-local-technical-closure-report.md), and the pinned original
source described below. Execution status: P0–P9 are complete locally; see the
[execution report](2026-10-17-upstream-1.1.0-integration-report.md) for final artifact
evidence, verified review fixes and external acceptance gates.
It extends the original behavior-preserving refactor with explicitly accounted 1.1.0
behavior/schema/OAuth changes. Its recovery gates govern this integration; the old
refactor's Git-revert guidance is insufficient once the new schema is in use.

## 3. Security model and review focus

Assets are credentials, grants, group identities, scope selections, hidden paths,
structured references and persisted user data. Actors include administrators,
ordinary/disabled/deleted users, optional applications, remote clients and concurrent
requests. Native ACLs remain required even when policy grants an operation.

Five review priorities and their owning phases:

1. **Unknown policy vs denial:** unreadable policy or uncertain group eligibility
   must not become an allow, an empty successful response or destructive revocation.
   Exercise Basic/Bearer, listing and calls, including `grantAnyOf` order (P3/P5).
2. **Concurrent commit/retry:** no partial config, stale receipt replay or false
   success; no SQL from app listeners inside a caller-owned transaction. Exercise
   rollback, lost connection, cache reset and real deadlock boundaries (P2/P3/P7).
3. **Recreated identities and withdrawn clients:** old codes/tokens must not revive
   after regrant, account/group recreation or off/on client cycles; unrelated fresh
   credentials must survive cleanup (P3/P4/P7).
4. **Hidden aliases and references:** an excluded/out-of-scope node must not leak
   through a mount, folder URL, Talk attachment, task ATTACH, preview or error. Keep
   positive controls for visible resources and avoid mutating stored DAV data (P1/P5).
5. **Upgrade and recovery:** original credentials/preferences and schema identities
   survive upgrade; rolling application files back alone must not resurrect revoked
   credentials. Rehearse coordinated recovery with service closed (P2/P7/P9).

The upstream `PolicyWriter` is 1,485 lines. Split command families directly into
these owners; do not first introduce that entire service and promise later removal.
Preserve the transaction algorithm as one reviewed unit instead of splitting its
begin/commit/rollback operations among command objects.

Required inter-phase contracts:

- `PolicyTransaction::runAdmin(string $expectedRevision, array $uids, Closure
  $prepare, Closure $apply): array` and `runInternal(array $uids, Closure $prepare,
  Closure $apply): array` retain the upstream result fields `revision`, `changed`,
  `commandId`, `cleanupPending`. Preparation is outside a transaction; apply runs
  under the mutex. Supply a single `PolicyAttempt` explicitly to internal mutation
  collaborators for state, outbox and cut tracking; never start a nested writer.
  Define preparation as `Closure(array $observed, string $commandId): mixed` and
  application as `Closure(mixed $prepared, PolicyAttempt $attempt): bool`. The
  attempt exposes the locked state, command ID and outbox plus explicit cut
  tracking; it cannot commit, roll back or escape its callback. Adapt all command
  families directly to this final interface, without an old callback adapter.
  `PolicyTransaction::assertUsable(): void` is the same abandoned-context gate
  consulted by resolution and reads; it must not be a separate mutable flag there.
  `underMutex(Closure $local): mixed` retains the upstream lock-only execution
  contract for session deletion: reuse `runInternal`, return the callback value,
  and do not advance revision for a credential-row deletion alone.
- Move upstream `runCredential`, `consent`, `processCauses`, `revokeCredentials`
  and `revokeObserved` into `OAuth/Revocation/CredentialCommands.php`, preserving
  their parameter/result contracts. Move `applyCells` to `GrantCommands`,
  `restoreReceipt`/`receiptUsers` to `ReceiptUndo`, group preview/save to
  `GroupGrantCommands`, and `setResourceScope` to `ResourceScopeWriter`. Put
  `setGlobalEnabled`/`adminSetGlobalEnabled` in `ServiceCommands`, and
  `setEligible`/`setConnected`/`setGrant`/`resetOverride` in `GrantCommands`.
  Counter increment belongs to `DecimalCounter`, not a surviving writer facade.
- Extract `holdLifecycles` into `Access/Grants/Groups/LifecycleHolds.php`, with an
  explicit active `PolicyAttempt`; consent, exchange/refresh, eligibility reset
  and undo share it. Preserve active-row CAS renewal under the same mutex. A lost
  renewal invalidates the snapshot; no nested transaction or remote I/O is allowed.
- Receipt undo must apply grant and scope cells in one transaction, not call the
  top-level grant/scope command methods. Extract transaction-local grant writes
  to `Access/Grants/Commands/GrantMutations.php` and scope writes to
  `Access/ResourceScope/ScopeMutations.php`; both accept the current attempt.
  `ReceiptStore` reads the existing outbox receipt rows, not a second receipt table.
  Keep the transaction kernel independent of these command families; its delivery
  dependency may use mappers and OAuth storage, never resolution or another command.
- `PolicyResolver::begin(string $uid, array $added = [], array $removed = [], bool
  $observe = true): PolicyOperationContext`; contexts close after the operation,
  including exceptions. Keep typed resolution outcomes, not a boolean cache.
- `Access/ResourceScope/ScopeReader::inScope(string $userId, string $module,
  string $resourceId): bool` and `assertReadable(string $userId, string $module):
  void`; unreadability throws `PolicyUnavailable` before native resource lookup.
- Change `ObjectStore::objectByUid(int $calendarId, string $uid, string $component):
  ?array` atomically with every Calendar, Tasks, reference and selftest caller.
  There is no optional component fallback or old-signature adapter.
- Preserve `FileReferenceScope::restricts(string $userId): bool` and
  `allows(string $userId, Node $node): bool`. Shared reference filtering must not
  import `Modules/Talk/AttachmentAccess`: extract only the needed share-ID parsing
  into its final platform owner and use it from Talk.
- Keep native enumeration separate from scoped tool access. Notes/admin/native
  selection retain plain exclusion/native access; a Files restriction must not
  silently become a Notes, Contacts, Deck or Talk module restriction.

## 7. Residual decisions and completion boundaries

Upstream documents an exclusion-list cache window: another process/node can update
appconfig while an already-warm node serves the previous list for approximately the
3-second core TTL plus request time. Preserve the measured test and report this as
an inherited limit; deciding to remove it needs an explicit security/product change,
not a silent refactor. Similarly, distinct narrow external mounts may use different
file IDs; tags on one storage are not automatically tags on another. Do not promise
cross-storage protection absent evidence. Policy freshness also has upstream
limits for native group existence/backend lists, app availability and memoized user
objects in long-running processes; clearing official policy caches is not a promise
that every native subsystem refreshed. Preserve the resolver's documented boundary
and add host evidence before making stronger revocation/freshness claims.

Federated shares, advanced groupfolder ACLs, some native reference cases, real
client UX/CSP/themes and SMTP have incomplete or separate upstream evidence. Keep
these named in the execution report. Group-lifecycle races documented by upstream
remain subject to real tests and review, not a new guarantee of atomic native events.

Implementation can finish locally while human translation review and native/remote
