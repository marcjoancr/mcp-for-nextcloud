## P2 — Transaction kernel, schema and durable events

The kernel has one official connection, one mutex and bounded retries (three
attempts, two waits of 25–100 ms). Preparation runs outside the transaction; local
callbacks receive a `PolicyAttempt`, invalidated on exit. A fresh outbox shares the
logical command ID across retries. Revision CAS and event persistence commit with
local writes; failed rollback, uncertain commit and failed cache invalidation
abandon the shared context. Lock-only work returns its value without changing the
policy revision. A cut alone does change the revision.

Four original migration identities and the install/post-migration seed are retained.
Schema tests cover fresh installation, additive upgrade and reexecution without
resetting existing state. Decimal counters and opaque identity keys retain their
original semantics. Receipt storage checks ownership before expiry and validates
the complete payload. Delivery retries cannot undo a committed revocation.

Phase allocation details:

- `DecimalCounter`, `PolicyUnavailable` and `PolicyLimits` are shared policy owners;
  the inventory reflects their final locations. The limits owner contains only the
  persisted command bounds (50 users, 2,500 cells, 600/120-second lifetimes).
- The event processor needs generation-qualified cleanup and expired-row deletion;
  those three OAuth storage methods and their doubles are integrated now. Issuance,
  lifecycle consumers and job registration remain P3; managed clients remain P4.
- The resource-scope schema test inventories only current direct mapper consumers.
  P3/P5 must extend that explicit list with their final owners, without allowing
  arbitrary tool access to the mapper.
- `IRepairStep` adds one entry to each pinned native API capture, preserving all
  other fields. As upstream specifies, `IUserConfig` is required on Nextcloud 32–35;
  its obsolete NC31 fallback entry is removed. All other historical NC31 API cases
  remain, and declaring NC31 supported again would require resolving this gap.

## P3 — Identity, groups, revocation and existing administration controls

Implemented in the final capability owners. Grant, service, group, credential and
receipt commands share the transaction kernel through explicit dependencies; local
mutations require a live `PolicyAttempt`. `LifecycleHolds` renews the precise group
generations used by admission. Resolution distinguishes Allow, Deny and Unknown,
with individual overrides before trusted native group grants and defaults. Known
Allow wins across alternatives; an unavailable policy fails the whole request.

OAuth issuance, exchange, rotation and replay use user generations and the global
epoch. User and group listeners preserve deferred causes outside caller-owned
transactions; reconciliation and cleanup jobs are registered. Scope snapshots and
conservative deletion cleanup are real, mandatory dependencies, while all three
scope activation flags remain closed until P5 finishes their consumers.

The existing matrix sends one atomic command for a bulk edit and uses the server's
actor/revision-bound receipt to undo it. Service and Logs controls send their
snapshot revision too. A shared page-local channel propagates only a confirmed
single-step commit to sections on its exact predecessor; a no-op, post-commit jump,
conflict body or late response cannot rebase unrelated edits. Conflicts, missing
revisions and uncertain writes reload authoritative state without automatic replay.
Expired receipts remove undo; undo never recreates credentials.

MCP discovery/execution, prompts and resources preserve unknown-policy semantics.
Checkout now keeps the complete use of a link in the owner's operation snapshot;
unavailable policy returns HTTP 503 with `Retry-After: 1`, leaves the token unspent
and clears the context on exit. The consent template shows temporary unavailability
without presenting an authorization form.

Focused evidence includes 1,085 resolution/OAuth cases / 3,096 assertions,
312 group/listener/reconciliation/cleanup cases / 2,246 assertions, and 163
checkout/prompt/resource/tool cases / 993 assertions. The 177-case browser suite
passed, followed by 24 focused cases covering revision conflicts, uncertainty,
large decimal revisions and receipt undo across Chromium, Firefox and WebKit.
The repeated registered full gate passed: **7,061 PHP tests / 53,698 assertions**,
195 browser cases, 29 documentation-tool tests, both static-analysis scopes, lint,
documentation and package checks.

Validation corrections were explicit: the Files and Deck boundaries admit the shared policy

No broad API exemption, ignored failure or transitional writer facade was added.
