**Status: source and local regression review; full release acceptance remains open.**

update in [one PR](2026-10-18-upstream-pr-scope-proposal.md). It reviews the application
at `7d8873cafaaadedc479c2204c9ef75bb76062dcf`, unchanged through analysis head
`94431372f4030cfe2b345ad9c294ef9d29f9ae69`, against upstream

## 3. Inherited limitations that the PR must disclose

| Release items | Required treatment in the complete PR |
| --- | --- |
| L1, L2 — Group events, backend identity, stale processes and suspension races | Preserve conservative handling and administrator reconfirmation. No claim that refactoring solves lost-event windows, backend impersonation or long-lived process caches. |

| L4 — Tag exclusion boundary | Applies to this connector and the server's available metadata, not every Nextcloud/AI consumer or a remote federation server's tags. |
| L5 — Scope coverage and backups | Files/Calendar/Tasks only, per user; selected folder roots cannot be renamed. Backup writes have their dedicated boundary, while reading them still obeys access restrictions. |
| L6 — Conservative orphan retention | Missing/uncertain deletion evidence leaves restrictions in place; account recreation must not widen access. |
| L7 — Large-installation cost | Do not advertise runtime scaling improvements. The original group-operation cost remains a limitation unless separately measured and fixed; architectural scaling here means scaling development. |
| L8 — Audit visibility | Inspector/scope records depend on the host's info log level; no guaranteed audit trail is introduced. |

## 6. Manifest correction after the review

`mcp/appinfo/info.xml` from upstream `0911f9123a661968e707fc4c391adcf9d37c3e84`.
All bytes outside those six elements are unchanged. The complete corrected manifest
is byte-identical to the pinned upstream file; app version 1.1.0, registration,
dependencies, migrations, routes, runtime classes and localization catalogs retain
their existing identities. This is the metadata-only candidate-change category,
not a new implementation of group grants, resource restrictions or OAuth clients.

`ManifestDescriptionParityTest` reads the real XML and checks the reviewed summary
and eight formerly missing/truncated feature paragraphs in en, pt-br and es. The
small fixture records its immutable upstream source and original attribution;
tests need neither network nor Git history. Whitespace and unrelated manifest
fields are not frozen. Deliberate wording changes require reviewing this release-text
contract rather than blindly regenerating expected values from the changed manifest.
This protects the actual accidental content loss found in V0; it does not evaluate
translation quality or runtime functionality.
