The generic transport accepts an explicit `uncertainWrite` option; it does not
maintain an endpoint/domain table. A successful response with invalid JSON becomes
an uncertainty error only for opted-in writes. Ordinary reads/previews retain their
parse failure and real non-success HTTP status codes remain unchanged. Sections
own recovery and notices. Existing upstream behavior deliberately does not emit
saved events for unconfirmed group/scope writes; a possible broader cross-section
invalidation redesign is outside this integration.

An independent review found no remaining actionable integration defect after
checking this behavior against the pinned upstream contracts. That automated code
review does not replace the pending human security/accessibility/language reviews.
