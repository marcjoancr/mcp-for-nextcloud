## Failure and recovery

There is no automatic compensating DB restore, network reconnect, epoch reuse or command replay. Each uncertain action has a private durable intent/receipt and preserves known helper/network identifiers. A reviewer/operator must independently establish exact process/backend quiescence and inspect preimages before any recovery action. An uncertain helper can still exist after its host client exits. Intended epoch hashes and started/result receipts must be inspected even if metadata still contains the old rollback epoch; compute the actual DB epoch hash and compare, never infer commit from a vanished helper. A partial network release is not marked successful; the app remains stopped until separately resolved. Foreign artifact replacements are preserved and refused, never overwritten as rollback. Private backups survive every error.

A compatible rollback requires exact current owned entry hash and matching bundle manifest, complete known bundle sources and current metadata epoch matching the actual DB epoch. A missing/foreign/partial source state requires recovery, not an invented prior entry. Retirement rotates epoch before the entry disappears; every existing history row remains exact and previous captures become invalid. Reinstall creates another fresh epoch, never resurrects retired witnesses. Arbitrary external config/whole-DB removal+replay remains outside supported installer coverage, as ruled by the parent.
