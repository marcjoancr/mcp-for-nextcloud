# Native Forms guard

This companion is a source overlay for Nextcloud Forms **5.4.2**, upstream commit `066573fd592513a06f8b8624def8244e911efdfd`. It is separately installed with Forms; it is not part of the MCP application archive. The current admitted cells are Nextcloud 35.0.2 with PostgreSQL 16.15 or MariaDB 10.11.19. Other versions and SQLite are not admitted for guarded MCP writes.

## Prepare and install

Extract the official installable Forms 5.4.2 release archive, including its vendor dependencies. Run:

```sh
node native/forms-guard/prepare.mjs /absolute/extracted/forms /absolute/new/output/forms
```

Preparation verifies every pinned executable/configuration input, rejects extra executable sources and symlinks, preserves native source and validation, wraps the enumerated writer boundaries, installs companion classes, lints generated PHP and emits `mcp-guard-installed.json` with exact installed hashes. The output directory must not exist. The source remains untouched. The output is a modified, unsigned Forms distribution: the upstream signature does not authenticate the overlay. Distribution must include this companion source and its matching pinned upstream source offer; it must not claim to be an unmodified upstream release.

Install only during an authorized Forms maintenance window with a verified database and file backup. Run the normal app migration lifecycle after placing the overlay, even if Forms 5.4.2 was already enabled: disable and re-enable Forms while traffic is stopped. This applies all included migrations, including `Version050402Date20261113030000` for opaque effect payload references and `Version050402Date20261113040000` for managed sharing intents. Do not edit an active installation in place while requests/jobs run. Rollback requires maintenance and a reviewed restoration of the previous complete Forms code; companion tables retain historical evidence and must not be blindly dropped. This repository's preparation command does not deploy, publish or modify a live installation.

## Contract

`OCA\Forms\Mcp\Guard` provides `capabilities()`, `snapshot(uid, action, input)`, `apply(uid, action, input, revision, operationKey, fileManifest?, transfer?)`, `read(uid, action, input)`, `lookup(uid, operationKey, origin?)`, and `deferredRead(origin, action, input)`. Immediate calls require the same enabled native session actor. Snapshot, apply and lookup also require a private signed MCP origin; reads verify it whenever supplied. The origin is verified through the real MCP `FormsNativeAuthorization` bridge, including current actor incarnation, original connection, tool selection and grants. Artifact identities bind the invariant UID/incarnation/connection tuple, not a mutable whole proof. There is no UID-only artifact fallback. The MCP layer owns bounded model-visible projections and redaction. Raw trusted native data must never be copied unfiltered into public receipts.

`deferredRead` accepts `snapshot`, `forms_results_metadata` or `forms_results_page` only for signed summary/download/export/link origins. It uses fresh native actor-dependent services and a read-only scoped user session, checks explicit current results permission and any frozen owner reference, and checks the revision before/after reading. It never changes the global worker session. Deferred Circle-based authority/audiences remain unqualified because the pinned Circle service has mutable global session state without a safe scoped restoration contract. Owner, direct-user and group authority use native permission checks.

Writes use a conservative global row fence in the same primary connection/transaction as Forms. The ordinary native controller, mapper, import, share-review and background writer hooks share that fence. Every successful outer writer increments the generation. The SQL increment is bounded before integer overflow. Native validations execute inside the shared fence. Answer replacement rolls back completely on an insert failure; the last submission slot has one serialization order. Creation/clone, authoring, locks/state, sharing, DB-only response operations and administration invoke native controllers or validators.

A unique native operation key, HMAC of the input and sanitized receipt commit with the native DB mutation. A retry returns that key's existing receipt; a different input using the key is rejected. A lost commit acknowledgement must be resolved using `lookup`; absence after an ambiguous storage/commit error is not proof of no effect. Receipts persist opaque references and phases, not answer bodies or share/upload capabilities. `OCA\Forms\Mcp\BeforeEffect` identifies a proven authorization, source, revision, key, file-boundary rejection before any effect. A native OCS validation exception after work begins is not sufficient evidence of no file effect; it remains uncertain. Other exceptions must remain uncertain.

Native submission/share notification intents enter a DB outbox before commit. MCP intents retain encrypted immutable payloads in private appdata; durable rows contain opaque references. Dispatch claims the intent as uncertain before external invocation, then reacquires the Forms fence, verifies original MCP authority, current native ACL, owner, and an HMAC of bounded form/question/answer/share/audience dependencies. Intervening edits or revoked authority suppress dispatch. The actual native confirmation-mail worker repeats these checks and reads recipient/body from encrypted appdata; its job argument contains only an opaque reference. Native Activity/mail code can swallow delivery exceptions, so successful invocation is `attempted_unverified` and operations remain `partial`. No SMTP delivery guarantee is implied. Claimed intents never replay; pending intents after process loss remain pending for explicit reconciliation. Ordinary native UI events keep native behavior.

## Remaining qualification and extension points

The attachment/recovery primitive below supersedes the initial file-free guard. It rejects arbitrary nodes in destructive paths and unqualified linked automatic-export effects. Storage admission is limited to the exact tested implementations and configurations. Native user/group Files-sharing effects use the postcommit phase below. Circle Files-sharing effects remain unqualified. Whole-form recovery over its bounded limits needs continuation work.

New native classes under `src/` are automatically included in the generated exact-source manifest. Extend native actions and hooks only with corresponding runtime tests. Comments, linked persistent jobs, additional storage/provider qualification and complete native parity remain separate work. Database transactions do not make filesystem effects or notifications atomic.

## Managed attachment companion

The companion accepts private source streams only through `Guard::stageFiles` inside an approved `Guard::apply` callback. MCP must obtain those streams through the current Files scope, exclusion and native ACL gate. Native upload tokens remain private. The returned handles expire after five minutes and are bound to the signed actor incarnation, original connection, form and question; native validation and consumption share the revision transaction. Snapshot handle validation creates no staging files or recovery artifacts.

`Guard::apply` accepts a sixth, server-only approved `file_manifest` and an optional seventh transfer callback. Neither belongs in public tool arguments. The operation layer must persist the returned `files_phase` separately from database and notification outcomes. The manifest includes a digest of bounded recovery metadata, exact native file IDs and byte digests, and any Files sharing parent/recipient/identity effects. Generic form updates reject owner, lock, archive and export association fields that belong to dedicated operations.

Before a managed deletion, verified byte copies and a signed immutable metadata manifest are written to the private `forms_mcp_recovery` appdata area. Recovery records contain form, question, option, affected submission/answer and staged artifact metadata. No operation receipt contains answer text or raw upload tokens. A native storage wrapper rechecks managed identity and byte digests at the storage call, under the core's own mutation lock. Prefix-matched directories are candidate impact paths, never ownership evidence. Recursive native folder deletion and title-based folder merging are suppressed for approved operations; existing upload directories retain their paths after title changes. An unrelated file in a candidate destructive path refuses approval. Deferred question cleanup is fenced by durable question tombstones.

`forms_restore` takes a backup ID and restores into a new private closed form, with verified copies and new IDs. It never overwrites an existing destination, restores bearer tokens, recreates shares, enables confirmation email, or prunes the retained backup. A current original-form owner can restore; an original collaborator additionally needs current explicit results and results-delete authority. If the original form has been deleted, only its original owning actor can restore. Recovered standalone artifacts receive companion DB identities so subsequent managed cleanup remains safe.

Ownership transfer copies managed files into a fresh subtree belonging to the new owner and remaps native references after verifying bytes. Original source files are retained. The new owner must be enabled, and a pre-existing destination is refused. Files shares created by native Forms are recorded by exact share ID; matching unrelated user-created shares are not adopted or revoked. Shares that predate this identity hook and cannot be proven native-managed remain refused where cleanup would affect them.

Limits are ten source files, 25 MiB per file and aggregate per transfer, narrowed by native count/size/type rules. Recovery steps admit at most 100 affected responses, 100 files, 1 MiB metadata, 25 MiB file bytes and a 20-second capture budget. A response mutation captures only that response; submission captures only its referenced staged handles. Whole-form operations exceeding the bounded step require orchestration and remain refused by this primitive. Cross-storage moves are refused; explicit verified ownership copies are supported. Linked automatic exports remain a separate authority boundary. No claim about independent Activity or mail delivery follows from a verified Files phase.

Native expiry cleanup retains DB-identified MCP staging bytes even after handle expiry. It no longer recursively deletes timestamp-named temporary directories. Retention does not resurrect an expired handle; an approved form deletion can remove its managed staging bytes after verified recovery. No implicit cleanup or backup-pruning permission is inferred from upload approval.

User/group Files sharing is qualified on the tested PostgreSQL and MariaDB runtimes. `files_share_types` reports `[0,1]`. Circle and legacy user-group providers require independent qualification. The earlier PostgreSQL outer-transaction failure is addressed by the phase described below.

`NativeFormsOriginTest` additionally verifies delayed origin revocation, immutable event dependencies, actual native mail-job dispatch through a recording-only transport, null-session deferred reads, incarnation retirement of retained artifacts, numeric-grid recovery through native validation, and a real staged-file effect followed by an OCS exception. `tests/origin-fixture.php` seeds only disposable accounts using real MCP grant/selection/proof services. No production bypass is installed.


## Trusted destination mutation callback

`Guard::fileBoundary(uid, origin, node, childName, authorize, work)` protects one target allocation or content write. Existing files use `childName=null`. Allocation uses the parent folder and one validated filename. The server-only closures take no arguments. Admission verifies the signed original origin, qualified runtime/storage, native explicit results access and the callback's current Files checks. A no-op work closure performs preflight without allocating a missing target or modifying existing bytes.

The installed storage wrapper repeats admission immediately before native `file_put_contents` or write-mode `fopen`, after View acquires its exclusive lock. It checks target identity and captured ETag, live mount, underlying storage admission and native storage write permission. Native ETags can repeat when timestamps are preserved. Strict overwrite callers must also compare the approved preimage size and SHA-256 in the trusted callback using a bounded direct-storage read under the acquired lock. The wrapper is disabled in `finally`. Call allocation and subsequent content writing separately. Callback refusal is an ordinary uncertain exception because a prior stage may already have created an empty file or backup. The caller remains responsible for durable operation accounting and bounded source/destination approval. This API opens no additional Forms transaction.

The current tested sink callers use the original enabled native session actor. Deferred Circle authority remains subject to the authorization limitations described above. The qualified fresh principal graph is described below. The parent integration must rerun the web journey against the final generated companion.

During approved multi-file deletion, the original impact and recovery evidence remain immutable. After each approved file deletion returns and its storage absence is verified, request-local progress records that exact ID. Subsequent Files-scope checks cover the remaining files, source files and parent effects. An unexplained missing file still refuses the operation.


## Fresh native principal and configuration graph

`Guard::assertPrincipal(uid, requiresAdmin=false)` checks current native principal authority independently of the worker session and the MCP origin bridge. It verifies the qualified runtime/source, current database-backed user existence and enabled state, native per-user Forms/MCP app enablement, and native administrator role when requested. Native role checks preserve the remote-address restriction for the original actor. Guard actor/admin admission, native validators, result permissions and recovery creation policy use this graph.

The graph clones exact-source-qualified native user, group, AppConfig, UserConfig and AppManager objects. Native configuration getters preserve all nine Forms setting types and defaults. Scoped caches start empty. Shared AppConfig reads are bypassed, while native configuration writes still invalidate the shared cache. Scoped controllers receive these dependencies. Global session and container bindings remain intact.

Only the pinned core database user and group backends are qualified. Unknown backend implementations and nonempty `dbreplica` configurations refuse admission. The latter also sets native capabilities to unqualified because the pinned core can route reads outside transactions to replicas. `PrincipalSources.json` pins the source files used for private scoped-state construction and is covered by the generated companion manifest.

`NativeFormsPrincipalTest` exercises independent-process user/app/group/admin revocation after caches are warm, current positive administrator grants, a disabled actor waiting on the real native fence, group-restricted apps and group form shares, null-session principal checks, current native controller validators, typed configuration defaults and creation restrictions, unknown backends, and replica refusal. Scope construction leaves the original warm objects intact. System configuration files retain native request-local semantics, including `allowed_admin_ranges`. Changing those files during a request is outside this verified database-backed freshness slice.


## Read-only answer preflight

`Guard::preflightAnswers(uid, action, input, revision)` validates converted native answers for submission and full or own-response replacement before the MCP journal reserves an operation. The private input retains the signed original origin. Admission checks fresh principal/form authority, current submission and editing limits, native semantic validation, and revision equality before and after inspection. Clone previews also require current native creation permission and source edit access.

`AnswerFiles::inspect` translates opaque upload handles privately after checking actor incarnation, connection, expiry, form/question identity, current storage admission and bounded file digests. Short-lived shared read locks protect these reads. Repeated previews preserve upload consumption, Forms rows, revision, recovery artifacts and queued effects. Apply repeats validation and consumes handles inside the native fence. Existing submitted files require fresh upload handles for replacement, following the pinned native edit flow. The `answers_preflight` capability follows exact source/runtime qualification.

`NativeFormsAnswerPreflightTest` covers all thirteen native question families, legacy datetime, date/time ranges, numeric-grid zero, semantic refusals, repeated file previews, changed/expired/consumed handles, submission limits, own anonymous-response refusal, stale revisions and clone creation/edit restrictions.


## Postcommit managed Files sharing

The exact native ShareApiController folder/share block records a durable intent inside the Forms transaction. A primary-session advisory lock remains held across its commit and the immediate postcommit drain. The native ShareManager runs with autocommit after a one-shot uncertain claim. PostgreSQL uses `pg_advisory_lock`, while MariaDB uses `GET_LOCK`. Session identity checks and `finally` release protect connection loss and nesting. An unrelated outer transaction or pre-existing session advisory lease is refused. Connections must be nonpersistent and retain a direct primary session across acquisition, commit and effects. Session-pooling configurations remain unqualified. An acquisition acknowledgement fault still releases its session lease, and uncertain release closes the connection. Qualification requires the applied `050402Date20261113040000` migration and pinned sharing/connection sources.

The real native folder lock precedes fresh original authority, storage, Files-scope and target checks. New allocations also check the newly assigned folder ID. Registration requires successful mkdir evidence for the final folder from this operation. A concurrent existing final folder remains outside managed ownership. User/group creation runs a scoped clone of the pinned native sharing graph, retaining its validators and existing event hooks. A provider override rechecks original authority and the exact approved recipient, owner, node, type and permissions immediately before native create/delete writes, after native pre-events. It records IDs returned by the actual native INSERT path. Every scoped factory route is restricted to the guarded user/group provider, including provider-ID lookup, enumeration and registration. A concurrent matching share returned by Manager is accepted only when its exact ID was already managed. The companion never adopts an unrelated matching tuple.

MCP intents retain encrypted original actor/incarnation/connection proof and complete approved file impact. Ordinary UI intents bind the current authenticated request, its exact user object and an in-memory keyed credential-version digest. That path works with MCP globally disabled and has no cross-request replay. Credential changes conservatively invalidate an in-flight native UI share. All mapped removals use exact IDs. A direct primary query of the qualified `ocinternal` ID proves absence before retiring metadata. An unresolved API object with a remaining share row retains its mapping.

`share_removals` carries bounded exact collaborator-share impacts for form deletion. A previously verified mapping can be removed after a partial unshare deleted its Forms share row, using encrypted verified creation evidence and a fresh explicit form-deletion approval. Only verified completed byte deletions are removed from subsequent live file-impact checks. Original approval and recovery evidence remain immutable.

Core Files-share event attempts use the existing native effect journal. Verified Files changes can therefore return partial state with `files_share` events marked `attempted_unverified`. Unknown acknowledgements retain uncertain evidence and never replay automatically. Ordinary UI failure messages state that the Forms change committed when its Files phase remains uncertain. Pending intents after process loss require explicit reconciliation.

The migration can be applied by Nextcloud's native `OC\DB\MigrationService` using the concrete `OC\DB\Connection` service. The disposable tests call `migrate('050402Date20261113040000')`. Nextcloud 35 does not expose the older `migrations:execute` command. The generated overlay and migration must be installed together before enabling this capability.

## Bounded own results and public submission schema

The `own_response_pages` and `public_submission_form` capability flags follow the same exact source/runtime qualification as guarded operations. The corresponding new actions are advertised only while qualified. `forms_read_own_responses` uses native result admission, so identified prior submitters retain their own native result access after a direct share is removed, including expired or archived forms. Every caller, including an owner with full results permission, receives only exact UID rows. Anonymous native identities do not become caller-owned through a submission ID or public share.

`forms_read_own_response(id, submission_id, offset=0, limit=50)` continues that row's answers in ascending answer-ID order. The plural action orders submissions by timestamp descending and ID descending and returns a separately bounded first 50 answers per row. `forms_list_response_files` admits explicit results access or an exact own row after native result admission and pages file-answer references in answer-ID order. Returned references still require independent MCP Files scope and native Files visibility. A private exact `_mcp_file_id` selector preserves the existing save adapter's explicit-result lookup beyond the first page; it returns at most one matching reference. Own-file saving retains its separate existing results and sink predicates.

`forms_read_submission_form(share_hash, question_id?, offset=0, limit=50)` resolves the exact current public share before calling native submission admission on every preview/page. It accepts no caller form ID. Without a question selector it pages active questions using native order, file-accept and minimum-choice semantics; with a selector it verifies exact active form membership and pages that question's options in native order and ID order. Public metadata excludes owner, access, shares, hashes, linked paths and confirmation-mail bodies. A public hash adds no results, edit or comment authority.

All public pages use query-side limit-plus-one, default 50 and maximum 100, and a private `_mcp_page` continuation envelope. Every returned page stays within 1 MiB; oversized data refuses with a smaller-page request. Read previews do not load full question/option/answer collections. A read-scoped submission mapper supplies the same native no-search count as a SQL scalar, keeping native result admission from materializing all prior submission IDs; writes and own-edit predicates retain their original mapper. Fresh original MCP authority and the source revision are checked around reads; these reads do not reserve operations, stage uploads, acquire mutation locks or write native rows.

`NativeFormsOwnPublicTest` covers native permission parity, ownership, anonymous exclusion, stable submission pages, answer/file continuation, public schema semantics and revocation, exact response/question preview admission, fresh grants, byte budgets and real emitted SQL bounds. Files visibility and real MCP HTTP publication remain adapter-level qualification responsibilities.
